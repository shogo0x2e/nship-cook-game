# もぐもぐキャッチ — 親子の料理体験 PoC

現在のトップページは、ログイン不要で1台の端末を親子で受け渡す配布用の体験です。年齢入力 → 食材キャッチ → 親がレシピを選択・確認 → 子どもが担当工程を見る → アンケート → 保存完了まで進みます。実際の調理の進行管理は含みません。

13食材と日常の料理12品を使い、親はお手伝いを選ぶ必要がありません。ゲーム中にもカメラプレビューを表示します。8歳以下と9歳以上で子どものアンケートの言葉・前提を切り替えます。構想5点の画像を見た後に、1世帯あたり月額（税込）の支払上限を尋ねます。

回答はサーバーの永続SQLiteに保存します。通信失敗時の保留・再送と6文字の受付IDに対応します。`?demo=1` の回答は通常集計から除外します。運営者の集計は `node scripts/export-surveys.mjs`、CSVは `--format csv --out /private/path/answers.csv` で取得できます。公開の回答一覧はありません。 Google Sheetsへの30分同期は[専用GASの手順](integrations/google-sheets/README.md)を参照してください（運営者の専用キーが必要）。詳しい流れと画面確認用HTMLは [試作の説明](design/recipe-prototype/README.txt) にあります。

体験IDと受付IDは同じ6文字のNano IDです（`0/O`、`1/I/L`を除外）。ページを閉じたり再読み込みした場合は新しい体験になり、入力を復元しません。体験中の画面移動・年齢訂正ではIDを維持します。未完了の明示的な離脱にはブラウザ標準の確認を出します（モバイルの強制終了等を除く）。ブラウザ識別用のUUIDのみをlocalStorageで再利用し、同じブラウザからの回答を分析時に確認できます。途中回答と最終回答はSQLiteに保存し、配信待ちデータだけをlocalStorageに保持します。

以下は、互換性のため `/legacy.html` に残した旧家庭アカウント版の説明です。

## 旧家庭アカウント版

大人のスマホと子どものタブレットで、同じユーザー名・パスワードにログインします。メール認証・6桁の参加コードは不要です。

## 使い方

1. 初めて使う大人が「アカウントを作成」から、家庭のユーザー名とパスワードを登録します。
2. 両端末で同じアカウントにログインし、「大人」「子ども」を選びます。画面は端末ごとに記憶し、自由に切替できます。
3. 子どもは大人の画面を待たず、食材キャッチを開始・再プレイできます。カメラなしでも遊べます。
4. 大人は後から最新1回の結果を確認し、食材を選び直して献立を選択します。
5. 大人は全工程を見守り、子どもには現在のお手伝いを大きく表示します。子どもの「できた」を大人が確認して工程を完了します。

子どもが再プレイしても、選んだ献立・調理進捗は保持します。献立向けの食材ヒントは最新1回で置き換えます。スコアチャレンジは、これとは別に最近100回の試用記録と自己ベストを保存します。

## 二つの遊び方

- **いつものキャッチ**：従来の未就学児向け体験。好きな食材を取り、3食材のお皿を3枚作ると終了します。点数はつきません。
- **スコアチャレンジ**：学年で限定しない一般向け試作。3秒のカウントダウン後、45秒間キャッチします。キャッチ100点、すばやさボーナス0〜100点、3個ごとにお皿完成ボーナス150点。どの食材も同じ配点で、見送りの減点はありません。少しずつ落下が速くなります。

自己ベストは同じ家庭アカウント内で、操作方法（カメラ／カメラなし）と使用可能な食材が同じ場合に比較します。45秒の完走記録だけが自己ベストの対象です。一時停止や検出が途切れた時間、最初のカウントダウンは45秒に含めません。途中終了も試用記録には残ります。ゲーム途中の再読み込みは進行を復元しません。

チャレンジ終了後、任意で「毎日使えそうか」「その理由・使う場面」「学年など」「楽しさ」を回答できます。主に確かめたいのは毎日使えそうかで、楽しさは補助の質問です。回答した意向と実際のプレイ日時は分けて保存します。大人画面の「スコアチャレンジの試用記録」からJSONでダウンロードできます。試用者ごとに家庭アカウントを分けてください。

今回のチャレンジでは、栄養学習や料理の指定を加えていません。得点目的で取った食材も含まれるので、献立を選ぶ前に今日食べたいものを本人に確認してください。

1家庭・1ゲーム・1つの献立を扱うPoCです。大人／子どもの切替には追加PINを設けていません。大人がタブレットへログインして渡す使い方ができます。

## ローカルで試す

Node.js 22.18以上、npmが必要です。ブラウザ検証にはGoogle Chromeを使います。

```sh
git clone https://github.com/shogo0x2e/nship-cook-game.git
cd nship-cook-game
npm ci
npm run setup:pose
npm run build
npm start
```

`http://127.0.0.1:8787/` が配布用の体験です。旧版は `/legacy.html` を開きます。2端末相当の旧版の確認は、ストレージを分けたブラウザやプロファイルで試してください。同じブラウザ内のタブはログインCookieと画面設定を共有します。

```sh
npm test
npm run build
npm run test:e2e
npm run test:challenge

# 開発時は2つのターミナルで起動
npm run relay
npm run dev
```

開発URLは `http://127.0.0.1:5173/`。Viteが `/api` を8787へ転送します。静的な `npm run preview` だけでは回答保存・認証・同期APIは動きません。

## 保存と認証

- アカウント、最新結果、食材の選び直し、献立、調理進捗、チャレンジの自己ベスト・最近100回の記録・任意回答をSQLiteへ保存します。既定は `data/cookgame.sqlite`。`DATA_DIR` で保存先ディレクトリを指定できます。
- サーバー再起動後も保存内容を復元します。旧版の一時的な部屋コードやメモリ内の部屋は引き継ぎません。
- ユーザー名は半角英数字・`_`・`-`の3〜32文字で、大文字と小文字を同じ扱いにします。パスワードは4〜128文字。名前・年齢・メール入力は不要です。
- パスワードは家庭ごとのランダムソルトとscrypt（N=65536、r=8、p=2）でハッシュ化します。平文は保存しません。
- ログインはHttpOnly・SameSite=StrictのCookieを使い、有効期限は7日です。HTTPS構成ではSecureを付けます。サーバーにはCookieのハッシュだけを保存します。
- ブラウザのlocalStorageには大人／子どもの画面設定だけを保持します。パスワード・ログイントークンをJavaScriptのストレージへ保存しません。
- 未認証の家庭データ取得・操作を拒否し、家庭ごとに状態を分けます。認証APIには試行回数制限を設けています。
- データの自動削除・メールでの回復はありません。チャレンジの試用履歴は最近100回までです。PoC終了時のデータ削除や忘れたパスワードは運営者が対応します。

運営者がパスワードを再設定する場合、永続データへアクセスできる環境で、権限を制限した一時ファイルから新パスワードを標準入力へ渡します。コマンドの引数やログにパスワードを書かないでください。

```sh
DATA_DIR=/path/to/data node scripts/reset-password.mjs <username> < /path/to/private-password-file
```

再設定時には、その家庭の既存ログインを失効させます。SQLite本体と永続ボリュームは公開せず、バックアップもアカウント情報として管理してください。

## HTTPS・本番構成

本番では、信頼されたHTTPSから利用してください。サーバーをリバースプロキシの背後へ置く場合は、実際の公開Originを設定します。

```sh
HOST=0.0.0.0 PORT=8787 DATA_DIR=/data \
ALLOWED_ORIGINS=https://cookgame.shogo0x2e.com \
APP_REVISION=<release-commit> npm start
```

- プロキシがHTTPでNodeへ接続する場合、Hostは `localhost:8787` などNodeが許可するアドレス・ポートへ合わせます。
- `DATA_DIR` はコンテナの外に永続化し、実行ユーザーだけが読み書きできるようにします。SQLiteとそのジャーナルを作成できる権限が必要です。
- `/api/version` はアプリのリビジョンと `family-account-v1` を返します。リリース確認に使えます。
- コードを戻す際にも永続データは削除しません。旧6桁コード版は家庭アカウントのDBを読みません。
- `production` ブランチによるリリース経路とVM/Docker/Tunnelの運用は、ホスティング担当の `homelab-infra/docs/cookgame-hosting.md` で管理します。

LANの通常のHTTPではカメラAPIを使用できません。ローカル検証用の証明書を作る場合は以下を使えます。端末の信頼設定は自動変更しません。

```sh
node scripts/create-local-cert.mjs <MacのLAN IP>
HOST=0.0.0.0 TLS_CERT=.local-certs/server.crt TLS_KEY=.local-certs/server.key npm start
```

証明書ファイルの生成だけでは端末から信頼されません。端末管理者がHTTPS証明書の信頼を判断してください。秘密鍵は共有しないでください。[カメラAPIのHTTPS要件](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)、[iOS/iPadOSの手動証明書](https://support.apple.com/en-us/102390)。

## カメラ・ゲームと食材

MediaPipe Pose Landmarker Liteを端末内で実行し、顔を丸く切り抜いたアバターへ肩・肘・手首の角度を写します。座ったまま肩より上に手を伸ばし、食材に触れると取れます。鏡の向きで表示し、体の位置と腕の長さは固定します。カメラなしでは従来のかごを指・マウス・左右キーで操作します。[アバター試作の起動・調整・検証](AVATAR-POC.md) を参照してください。

ゲームは左右に落ちてくる2つの食材から好きなほうを1つ選びます。「いつものキャッチ」は食材を3つのせたお皿を3枚作ると終了します（最大20組）。「スコアチャレンジ」は45秒間で、最大64組を提示します。キャッチやお皿の完成には音とアニメーションで反応します。選ばずに見送った組は、好みの判定に数えません。

**映像・画像・骨格座標は送信・保存しません。** 同期するのは食材のキャッチ数・選択・調理進捗です。モデルとWASMは同じサーバーから配信します。`setup:pose` は公式モデルをSHA-256検証して配置する準備用コマンドです。

キャッチは今日の好みのヒントで、顔や表情から気分を診断しません。取り逃した食材も苦手とは扱いません。大人が子どもに聞いて食材を調整してください。

タブレットを安定した位置へ置き、大人がそばで見守ってください。座ったまま横・上へ手を伸ばして遊べます。包丁・火・熱い器具・生卵は大人の担当です。食材の除外はアレルギーの安全性を保証しません。全材料・製品表示・調理環境・温度・食べやすさを大人が確認してください。

## 検証と実装の入口

実施した確認と残る実機確認は [QA.md](QA.md) を参照してください。`npm run test:e2e` は独立した2ブラウザで登録・ログイン・親不在のゲーム・最新結果・調理・再プレイ・再接続を確認し、`test-results/` にJSONとPNGを保存します。実カメラは使用しません。

- `src/main.ts`: 家庭ログイン、大人／子どもの画面。
- `src/session-client.ts`: Cookie認証API、画面設定、ポーリングと再接続。
- `server/account-store.ts`: SQLiteアカウント、ソルト付きハッシュ、ログインセッション。
- `server/family-store.ts`: 家庭の永続状態、親なしゲーム、最新結果と調理進捗の分離。
- `server/session-store.ts`: 入力検証・調理工程の遷移。旧版の部屋ストアは内部互換テスト用で、公開APIへは接続しません。
- `src/content.ts`, `src/shared.ts`: 食材・レシピ・担当工程。
- `src/game-scene.ts`, `src/pose.ts`: 端末内のゲーム・姿勢推定。
- `src/challenge.ts`, `src/challenge-view.ts`: チャレンジの配点・記録検証、結果と毎日利用の任意回答。

ゲームのキュレーション用worktree `../nship-cook-game-curation`（`feat/game-curation`）とは独立して開発します。統合時に共有ファイルを調整し、検証済みコミットを公開します。
