# もぐもぐキャッチ — 2端末ローカルPoC

**大人はスマホ、子どもはタブレット。** 食材キャッチで見つけた「今日気になる食材」をヒントに、親子で分担できるレシピを選び、作業の進み具合を共有します。
どちらの大人でも使える設計で、家族プロフィール・名前・年齢・夫婦のスケジュール入力は不要です。

## まずMacだけで試す

Node.js 22.18以上が必要です。依存関係と姿勢モデルは、以下の手順で準備します。

```sh
git clone https://github.com/shogo0x2e/nship-cook-game.git
cd nship-cook-game
npm ci
npm run setup:pose
npm run build
npm start
```

1. Macのブラウザで **http://127.0.0.1:8787/** を開き、大人として部屋を作ります。
2. 別のタブで同じURLを開き、子どもとして6桁コードで参加します。
3. 大人側でゲームを開始。まずはカメラなし操作で一連の流れを確認できます。
4. ゲーム後、大人側で食材を確認・選び直し、レシピを選びます。
5. 大人が工程を子どもへ渡し、子どもが「できた」と報告。大人が確認して完了にします。

大人タブを複製するのでなく、新しいタブを開いて参加してください。接続情報はタブごとの `sessionStorage` に置きます。
別タブは状態共有の確認用で、タブレットのカメラ性能を検証したことにはなりません。背景タブでゲームが一時停止する場合は、2つのブラウザウィンドウを並べるか実端末を使ってください。

## スマホ＋タブレットで試す

### A. カメラなしで2端末同期を確認

Mac、スマホ、タブレットを**信頼できる同じLAN/Wi-Fi**につなぎます。

```sh
npm run build
HOST=0.0.0.0 node server/server.ts
```

スマホとタブレットの両方で `http://<MacのLAN IP>:8787/` を開きます。MacのLAN IPは「システム設定 → Wi-Fi → 接続中ネットワークの詳細 → TCP/IP」で確認できます。

- スマホで大人の部屋を作成し、タブレットで6桁コードを入力します。
- 大人画面と子どものカメラなしゲーム・作業表示はHTTPでも試せます。
- **通常のLANのHTTPではカメラAPIを使えません。** タブレットの `localhost` はMacではなくタブレット自身です。
- LAN起動は同じネットワークからこのアプリに接続できる状態にします。公共Wi-Fiでは使わず、試し終えたらターミナルで `Ctrl+C` して止めてください。
- Macのファイアウォール等に遮断された場合は、その設定を大人が確認してください。この実装は設定や権限を自動変更しません。

### B. タブレットのRGBインカメラを使う

**タブレットのブラウザが信頼するHTTPS証明書が必要です。** 既に利用できる証明書がある場合は、その証明書・秘密鍵を指定します。

```sh
HOST=0.0.0.0 \
TLS_CERT=/path/to/server.crt \
TLS_KEY=/path/to/server.key \
node server/server.ts
```

スマホ・タブレットで `https://<証明書に含まれるMacのIPまたは名前>:8787/` を開きます。URLのIP/名前は証明書のSANと一致する必要があります。

ローカル検証専用の証明書ファイルを作る補助スクリプトもあります。

```sh
# 192.168.1.23 は実際のMacのLAN IPに置き換える
node scripts/create-local-cert.mjs 192.168.1.23

HOST=0.0.0.0 \
TLS_CERT=.local-certs/server.crt \
TLS_KEY=.local-certs/server.key \
node server/server.ts
```

このスクリプトは、Mac標準のOpenSSLで `.local-certs/` に専用CAとサーバー証明書を作るだけです。
**証明書を生成しただけでは、スマホ・タブレットから信頼されません。OS/ブラウザへのCA導入・信頼設定は自動で行いません。**

- 自分で管理する検証端末に限り、必要性を理解した大人が、端末の公式手順に従って `ca.crt` の導入・信頼を判断してください。端末管理者の制限がある場合は管理者へ確認してください。
- 証明書警告を無視して使うのではなく、信頼された証明書の状態を確認してからカメラを許可してください。
- `ca.key` と `server.key` は秘密鍵です。他の端末へ送信したり共有したりせず、Mac内で管理してください。生成時の権限は0600です。
- CAは90日、サーバー証明書は30日で期限切れになります。既存ディレクトリには上書きせず、新しい出力先は `--out <新しいディレクトリ>` で指定できます。新CAを作った場合、以前のCAを信頼していても新CAは別物です。
- IPが変わったら、証明書の対象IP/名前との一致を再確認してください。
- IPではなく `cook.local` などの名前で接続する場合は、名前解決と証明書SANを用意し、サーバーに `ALLOWED_ORIGINS=https://cook.local:8787` も指定します（使うURLそのものを指定）。通常のLAN IPでの接続には不要です。
- 公開トンネル、新規アカウント、外部公開、信頼ストア変更、ファイアウォール変更は行っていません。

カメラAPIのsecure context要件は[MDN](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)で確認できます。iOS/iPadOSでは手動導入した証明書は自動的にSSLで信頼されません（[Apple公式説明](https://support.apple.com/en-us/102390)）。本作業では信頼設定を変更していません。

**実スマホ・実タブレットの接続と実カメラの精度・速度は未検証です。** 独立した2ブラウザーによる一連の同期と、Node内だけでCAを指定したHTTPSは検証しました。実施範囲と画面は [QA.md](QA.md) を参照してください。

## 体験と操作主体

- **大人のスマホ**: 最小設定 → 部屋作成・接続 → 子どものゲーム結果を確認 → 食材を選び直す → 献立選択 → 全工程と子どもの担当・進捗を見守る。
- **子どものタブレット**: 部屋に参加 → 食材キャッチ → 大人の選択を待つ → 今のお手伝いを大きく見る → できたと報告。
- 子どもの完了報告だけで工程を確定せず、大人の確認を経て次に進みます。
- 親のスマホを子どもへ渡す運用ではありません。家族全員のアカウント共有・複数の大人の同時管理は、今回のPoCの範囲外です。

ゲームは顔・表情から好き嫌いや気分を推定しません。キャッチ回数は**今日の好みのヒント**であり、取り逃した食材を「苦手」と扱いません。大人が子どもに聞いて調整してから献立へ進みます。

## カメラと遊び方

- MediaPipe Pose Landmarker Liteをブラウザ内で実行し、1人の左右の肩の中点にかごを追従させます。映像は鏡の向きです。
- カメラなしでは指・マウス・左右矢印キーで操作できます。
- タブレットは安定した位置に置き、大人が近くで見守ってください。歩く・走る・ジャンプする必要はなく、座ったままでも遊べます。
- 明るい場所で上半身が映る距離を確保してください。複数人から子どもを識別する機能はないため、遊ぶ子どもが中心に映るようにしてください。
- 推論はLiteモデルを低頻度で実行し、GPUが使えなければCPUへフォールバックします。低性能端末では描画が止まる可能性があり、実機測定・ウォームアップ・Worker化は今後の検証点です。

## データの扱い

**映像・骨格座標はタブレットの外へ送信しません。食材の選択・ゲーム結果・作業進捗は、同期のためMacへ送ります。**

- MacのNodeサーバーが部屋状態をメモリ内で中継し、大人と子どもの端末へ共有します。クラウドサービス・外部API・データベースは使いません。
- 部屋はサーバーの再起動、明示終了、参加・操作から2時間の無操作期限で消えます。ポーリングだけでは期限を延長しません。ブラウザの再読み込みだけでは部屋状態を消しません。
- タブごとの接続トークンは `sessionStorage` に保持します。ブラウザ履歴を使った再接続や家族の永続アカウントはありません。
- 6桁の参加コードは同じLANの他人に伝えないでください。外部公開向けの認証・運用設計ではありません。
- 同じネットワーク内でもHTTPは暗号化されません。実家庭データを扱う利用やカメラ利用では、信頼されたHTTPSを使ってください。
- カメラの録画・静止画保存、解析SDK、広告、外部フォント、外部レシピサービスはありません。モデル準備後、外部CDNへの接続も不要です。

同期は通常約0.8秒周期です。「つながっています」はその端末とMacの接続状態です。調理中は再読み込みで進捗を復元できます。ゲーム中の再読み込みでは未送信のキャッチと残り時間は消え、準備からやり直します。結果の送信に失敗した場合、そのページを閉じずに「もう一度送る」で再送してください。

子どもは1部屋につき1端末です。子どもの元のタブや接続トークンを失った場合は、大人が部屋を終了し、新しい部屋へ参加してください。

## 食材・調理の安全

「使わない食材」と卵・乳の除外は、**アレルギーの安全性を保証しません**。全アレルゲンに対応した仕組みではありません。
レシピは固定のPoCサンプルです。大人が全材料・製品表示・調理環境を確認し、年齢・発達・食べやすさ・温度を調整してください。
包丁・火・熱い器具・生卵は大人が担当し、子どもの作業中も見守ってください。

## 開発・検証

```sh
npm test
npm run build

# カメラなし・2ブラウザーの一連の同期検証（Google Chromeを使用）
npm run test:e2e

# 開発時は2つのターミナルで実行
npm run relay   # ローカルAPI: 127.0.0.1:8787
npm run dev     # Vite: 127.0.0.1:5173、/apiをローカルAPIへ転送
```

`npm run preview` の静的配信だけではAPI同期は動きません。全体の確認には `npm start` を使ってください。
以前の開発サーバーを起動したまま引き継いだ場合は、一度止めて起動し直してください。API転送は `vite.config.ts` の新しい設定を読み込む必要があります。

`npm run test:e2e` は `npm run build` 後に実行します。外部公開せず、一時的なloopbackサーバーと2つの独立したブラウザーコンテキストを使います。実カメラは使用せず、カメラ権限拒否はテスト用の置き換えで確認します。`test-results/` にJSONと画面PNGを保存します。Chromeがない環境ではPlaywright対応のブラウザーを用意し、`E2E_BROWSER` にチャネル名を指定してください。

`npm run setup:pose` は公式Google配布の固定LiteモデルをSHA-256検証して `public/pose/` へ配置し、インストール済みMediaPipeからWASMをコピーします。約35MBのアセットはGit対象外です。別Macでは再度準備してからビルドしてください。
開発サーバーの `/tests/pose-smoke.html` は、カメラを撮影せず空の合成画像でモデル初期化・推論を確認する補助ページです。

## 後からの登録・拡張

- `src/content.ts`: 食材とレシピ。材料、子ども工程、大人工程、アレルゲンを型付きで登録。
- `src/shared.ts`: 同期状態・操作と工程計画。工程ID、担当、前提工程を定義。
- `src/game.ts`: キャッチ・ヒント・除外・推薦順位の純粋関数。
- `src/pose.ts`: 端末内のカメラ・MediaPipe処理。
- `src/session-client.ts`: 同一originのAPI、タブ内の接続情報、ポーリングと再接続。
- `src/game-scene.ts`: カメラ/カメラなしのゲーム表示と未送信結果の再送。
- `server/session-store.ts`: 部屋状態と権限・遷移の検証。
- `server/server.ts`: ローカルHTTP/HTTPSと同一originのAPI・静的ファイル配信。

現段階の「登録」は開発者がデータを追記する方式です。利用者向け登録UI、長期の好み履歴、家族全員のプロフィール、クラウド共有は未実装です。

## 並行開発（Git worktree）

ゲームのキュレーション用には、別ディレクトリ `../nship-cook-game-curation` とブランチ `feat/game-curation` を使います。
それぞれの worktree は作業ファイルと未コミット変更が独立しています。アカウント機能も実装するときは別ブランチ・別 worktree を使い、共有ファイルの変更は merge 時に確認します。公開環境へのデプロイには、統合・検証済みのコミットを使ってください。

```sh
# 元のリポジトリで一覧を確認
git worktree list

# 作成済みのゲーム用 worktree へ移動
cd ../nship-cook-game-curation
npm ci
npm run setup:pose
npm run build

# 同じMacの別サーバーと衝突しないポートで確認
PORT=8788 npm start
```

各 worktree では依存関係・モデル・ビルド出力も個別に準備します。同一ファイルを別ブランチで変更した場合、merge 時の調整が必要になることがあります。
