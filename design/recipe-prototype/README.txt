・本番ルートは index.html → src/experience-main.ts。ログイン不要の1台体験。
・画面確認用は node design/recipe-prototype/serve.mjs → http://127.0.0.1:8793/design/recipe-prototype/
・画面確認用HTMLでもカメラ・アバターのゲームを試せます。カメラなしの画面確認はタップによる再現です。
・?demo=1 を付けるとデモ回答。本番の集計から除外します。

流れ
01 親が説明を読み、体験する子どもの現在の年齢だけを入力。
本番の入口や以前の #camera / #game を開き直しても、説明画面から始まる。ゲームはそのページで開始ボタンを押したときだけ起動する。途中の回答・送信待ち・受付番号は保持する。
02 は「カメラを起動して、ゲームを始める」の1ボタン。押すとゲーム画面へ移り、その画面内で顔・両ひじ・両手を自動確認。2秒確認できると、そのままプレイが始まる。カメラの再起動や追加のタップは不要。
輪郭と表示確認： http://127.0.0.1:8793/design/recipe-prototype/camera-preview.html
初回は npm run build を実行して、自動検出用のブラウザモジュールを生成する。
03 同じ役割の食材同士から選ぶゲーム。開始前は大きな映像で自動確認し、開始後はゲーム画面内の右下に、映像全体を小さく表示する。
04 点数と食材 → 05「親にわたしてください。」
06-A 親が写真からレシピを選択 → 06-B 材料・作り方・提案された分担を確認。
07 子どもが料理写真と担当工程の写真・説明を見る。実際の調理はしない。
08 子ども3問＋任意の自由記述 → 09 親2問＋任意の自由記述。
09 続き：今後の構想5枚（説明のみ）→ 1世帯あたり月額・税込の支払上限。
10 サーバー保存の確認後、受付番号を表示。

本番の保存
回答は既存の永続SQLiteと同じDBの experience_responses テーブルへ保存。
匿名の体験IDと端末の秘密キーで自分の回答だけを更新。キーはサーバーでハッシュ化。
送信失敗は端末に保留し、同じID・連番で再送。最終回答の保存確認後にだけ終了表示。
完了回答を遅れた途中保存で上書きしない。カメラ映像・顔画像・姿勢データは収集しない。
